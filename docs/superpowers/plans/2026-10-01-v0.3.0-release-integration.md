# Putnam Workbook v0.3.0 Release Integration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate the notebook editor and content-schema workstreams into a verified, same-signature v0.3.0 upgrade APK without losing existing user work.

**Architecture:** The release retains the existing application ID, signing key, user database, and notebook directory while replacing immutable content with schema/content version 2025.2. Automated acceptance covers the complete offline workflow; a release-to-release emulator rehearsal proves upgrade behavior before a versioned APK and checksum are delivered.

**Tech Stack:** Gradle/AGP 9.4, JDK 17, Android SDK 37 with target SDK 36, API 36 tablet emulator, PowerShell release verifier, retained JKS signing key.

**Spec:** `docs/superpowers/specs/2026-10-01-notebook-editor-and-content-schema-v2-design.md`

## Global Constraints

- Application ID remains `com.putnamworkbook.offline`.
- Minimum SDK remains 29 and target SDK remains 36.
- Release version is code `3`, name `0.3.0`; bundled content version is `2025.2`.
- Sign with the retained Putnam Workbook release key; never generate a replacement key.
- The manifest declares no INTERNET permission.
- Keep the existing v0.2.0 APK available as the upgrade baseline; do not overwrite or delete it.
- Deliver `dist/putnam-workbook-2025-v0.3.0.apk` and its SHA-256 sidecar.
- The 2020–2024 archive expansion remains paused.

## Review Focus

- Upgrading while a v1 notebook manifest exists must migrate and retain every visible page/stroke (Tasks 1 and 3).
- Progress last stored on Original Paper must normalize to Problem without resetting hint/completion state (Tasks 1 and 3).
- A failed pending save must not be reported as successfully exported or safely navigated away from (Task 1).
- The release APK must contain no original PDF, network permission, debug signature, or stale content database (Tasks 2 and 3).
- Finger/passive/active-capacitive input must remain usable after selection-mode integration on the target form factor (Tasks 1 and 4).
