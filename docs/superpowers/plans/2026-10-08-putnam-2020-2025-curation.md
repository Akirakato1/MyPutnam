# Putnam 2020–2025 Curation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Mathematical authorship and final review stay in the primary highest-reasoning context. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Curate the complete Putnam 2020–2024 corpus, re-audit the schema-v3 2025 corpus, and leave a locally verified six-year source library ready for one later release build.

**Architecture:** Strengthen the existing source-lock, year-audit, and render-review tools before authoring new material. Then curate one self-contained twelve-problem year at a time, newest first, using locked official sources, structured schema-v3 records, staged hints, prerequisites, controlled topics, and two-width visual review. This plan changes only source content, review evidence, and authoring tools; Android assets, app versions, `dist/`, signing, and APK assembly belong to the travel-release plan.

**Tech Stack:** Node.js 22, JSON Schema/Ajv, KaTeX, Playwright/browser screenshots, `pdf-lib` 1.17.1 for deterministic PDF metadata, Markdown review ledgers, official MAA source PDFs, and the established Putnam archive for independent TeX cross-checks.

**Spec:** `docs/superpowers/specs/2026-10-08-library-topic-search-and-travel-release-design.md`

## Global Constraints

- This plan runs after `2026-10-08-generic-library-topic-filter.md`; every problem is schema v3 with canonical identity `putnam/{year}/{A1..B6}`.
- Each year contains exactly A1–A6 and B1–B6 with unique ordinals 1–12, four ordered hints (`nudge`, `strategy`, `knowledge`, `outline`), at least one prerequisite, a complete solution, one or more substantial controlled topics, and HTTPS citations.
- Prefer official MAA statements and solutions. During execution, browse and verify each current official URL and downloaded byte stream; use an established archive only as an explicitly recorded fallback or independent cross-check.
- Source PDFs and TeX are development evidence only. Never copy them into `app/src/main/assets` or an APK.
- Preserve the competition label `putnam/2020`, even though that competition was administered in 2021.
- A review note may say `Render review: complete` only after the generated documents were inspected at 480 CSS px and 720 CSS px. Preview generation must work before that declaration.
- All year tools load `content-src/library.json` by default as established by the generic-library plan; curation commands pass `--catalog content-src/library.json` explicitly so catalog-dependent validation is visible.
- Topic tags describe substantial mathematics, not incidental notation. Hint stages must progressively help without collapsing into four paraphrases of the published solution.
- Final mathematical reconstruction, hint design, prerequisite explanations, topic judgment, and proof review stay with the primary highest-reasoning implementer. Parallel workers may acquire immutable source bytes, compute hashes, exercise tooling, or independently flag discrepancies, but may not author or approve the final mathematics.
- Stop after local source/audit/review completion. Do not publish Android assets, bump versions, assemble an APK, use signing secrets, or write `dist/` in this plan.
- Before Task 1, record the starting commit and snapshots of release-owned Android assets and ignored `dist/` paths; Task 7 compares against that baseline rather than relying on final `git status` alone.
- Do not add `Co-Authored-By` trailers.

## Review Focus

- A changed URL, redirect to an HTML error page, same-length byte mutation, wrong page count, or stale source lock must fail with the exact file and reason (Task 1 and each year task).
- A proof that matches a result but skips a necessary case, limit, equality condition, or convergence justification must not pass mathematical review (Tasks 2–6).
- Hints that reveal too much too early, prerequisites that merely restate the solution, or topic tags based on superficial symbols must be rejected (Tasks 2–6).
- The first-render workflow must not require falsely marking visual review complete, and narrow multiline mathematics must be examined at the actual reference-pane widths (Task 1 and each year task).
- The delayed 2020 competition must remain cataloged and displayed as 2020, not silently relabeled 2021 (Task 6 and Task 7).
